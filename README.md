# ДТЭК → Telegram через GitHub Actions

Проверка пяти адресов без включённого ноутбука. Chromium открывает сайт ДТЭК и получает график. Бот хранит выбор нескольких адресов отдельно для каждого чата; в группе выбор общий. Уведомления отправляются при изменении статуса, графика или объявленного экстренного режима.

## Запуск

1. Откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота из BotFather.
   - `DTEK_ADDRESSES_JSON` — JSON-массив адресов (пример ниже).
   - `STATE_KEY` — 32 случайных байта в Base64. Сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. Сохраните ключ: его замена сделает сохранённые подписки недоступными.
2. Закройте локальную Telegram-службу (окно CMD). Два процесса не должны одновременно читать команды одного бота. При действующем webhook удалите его перед запуском polling.
3. Откройте **Actions → DTEK monitor → Run workflow** и проверьте результат первого запуска.
4. Отправьте боту `/start`, дождитесь меню, отметьте адреса и нажмите «Сохранить выбор». После каждого нажатия дождитесь обновления меню. Старые локальные подписки автоматически не переносятся.

В группе добавьте бота с правом отправлять сообщения и используйте `/start@имя_бота`, `/addresses@имя_бота`, `/status@имя_бота`. В личном чате: `/start`, `/addresses`, `/status`, `/stop`.

Формат секрета с адресами (подставьте реальные значения; можно задать до десяти):

```json
[{"id":"address1","label":"Название адреса","street":"вул. Назва","house":"1","url":"https://www.dtek-kem.com.ua/ua/shutdowns"}]
```

Для области используйте `https://www.dtek-krem.com.ua/ua/shutdowns` и добавьте `"city":"с. Назва"`. Улица, город и дом должны точно совпадать с вариантами списка ДТЭК. Сохраняйте `id` при редактировании адреса, иначе потребуется повторный выбор подписок.

## Ограничения

Расписание настроено раз в пять минут. GitHub может задерживать или пропускать запуски; команды и кнопки тоже обрабатываются только во время запуска. Это не сервис с мгновенными ответами. В публичном репозитории расписание может отключиться после 60 дней без активности: проверьте Actions и включите workflow снова. [Документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

Стандартные GitHub-hosted runners бесплатны для публичных репозиториев согласно [правилам GitHub](https://docs.github.com/en/billing/concepts/product-billing/github-actions).

Сайт ДТЭК может блокировать серверный Chromium или менять разметку. До первого успешного запуска получение графиков на GitHub не подтверждено. При недоступности источника бот сообщает об отсутствии актуальных данных, а workflow отмечается как неуспешный. График не подтверждает фактическое наличие электричества; экстренные отключения распознаются по текущим объявлениям ДТЭК.

## Хранение и приватность

Токен и адреса читаются из Secrets. Подписки, Telegram chat ID, последние результаты и offset шифруются AES-256-GCM и сохраняются в `bot.enc` отдельной ветки `bot-state`; в открытом виде их нет в Git. Ключ хранится только в Secret `STATE_KEY`. История зашифрованных снимков видна публично. Не включайте отладочное логирование и не публикуйте секреты в issues. Workflow имеет право записи только для сохранения зашифрованного состояния. PR и push не запускают workflow.

Если сообщения отправлены, но запись состояния не удалась, при следующем запуске возможны повторы: отправку Telegram и сохранение GitHub нельзя объединить в одну транзакцию. При ошибке расшифровки запуск останавливается, состояние не сбрасывается.

Локальная проверка: `npm ci` и `npm test`. Исходники браузерного расширения и его bridge-key в этот проект не входят.
